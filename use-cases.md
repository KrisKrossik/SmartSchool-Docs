# Use Case 1: Колесо фортуны

**Вариант использования:** Покрутить колесо фортуны

**Область действия:** Образовательное веб-приложение

**Уровень:** Цель пользователя

**Основное действующее лицо:** Ученик

**Участники:** Отсутствуют

**Предусловие:** Пользователь находится на экране с «Колесом фортуны».

**Гарантии успеха:** Баланс пополнен случайным количеством монет, счётчик доступных вращений обновлён.

**Триггер:** Пользователь нажимает кнопку «Покрутить колесо».


## Описание:

1. Пользователь нажимает кнопку «Покрутить колесо».

2. Система проверяет условие: достаточно ли пройдено тестов (кратно 5).
  
3. Система показывает анимацию вращения колеса на экране пользователя.
  
4. Система останавливает колесо на выпавшем секторе и вычисляет выигрыш.
  
5. Пользователь видит поздравление и обновлённый баланс монет на экране.

## Расширения:

2.1. Система обнаруживает, что пройдено недостаточно тестов.

2.2. Пользователь видит сообщение «Пройди ещё N тестов, чтобы покрутить».

2.3. Сценарий завершается.

# Use Case 2: Прохождение тестирования, автоматическая проверка кода и подсказки

**Вариант использования:** Решение заданий внутри теста

**Область действия:** Образовательное веб-приложение

**Уровень:** Цель пользователя

**Основное действующее лицо:** Ученик

**Участники:** Сервис выполнения кода (бэкенд); Нейросеть (внешнее API) — только для подсказок

**Предусловие:** Пользователь открыл тест, состоящий из списка заданий (например, 3 задачи).

**Гарантии успеха:** Все задания решены верно, показан мем за завершение теста, начислены монеты.

**Триггер:** Пользователь выбирает задание из списка для решения.

## Описание:

1. Пользователь выбирает любое задание из списка теста (порядок решения произвольный).
   
2. Пользователь вводит решение (фрагмент кода на Python) и нажимает «Ответить».
 
3. Система отправляет код в бэкенд и показывает индикатор проверки.
  
4. Система выполняет код и прогоняет его по тест-кейсам; задание помечается как решённое, если результат совпал с ожидаемым.
  
5. Пользователь переходит к другим нерешённым заданиям и повторяет шаги 1–4.
    
6. Система фиксирует успешное решение последнего задания в текущем тесте.
    
7. Пользователь видит всплывающее окно со случайным мемом и уведомлением о начислении монет за пройденный тест.

## Расширения:

4.1. Результат выполнения кода не совпадает с ожидаемым.

4.2. Пользователь видит уведомление об ошибке с указанием, что вернулось и где разошлось с ожидаемым (подсказка автоматически не выводится).

4.3. Возврат к шагу 1 (пользователь может продолжить решать это задание или переключиться на другое).

## Альтернативный сценарий (Использование подсказки):

1.1. В любой момент работы над заданием (до или после попытки ввода ответа) пользователь нажимает постоянно доступную кнопку «Подсказка».

1.2. Система обращается к ИИ и выводит наводящий текст для текущей задачи.

1.3. Пользователь использует информацию и возвращается к шагу 2.

# Use Case 3: Ежедневный вход (Огонёк / Стрик)

**Вариант использования:** Поддержание серии ежедневных входов

**Область действия:** Образовательное веб-приложение

**Уровень:** Подцель пользователя

**Основное действующее лицо:** Ученик

**Участники:** Отсутствуют

**Предусловие:** Пользователь имеет зарегистрированный аккаунт.

**Гарантии успеха:** Счётчик дней подряд («огонёк») актуализирован и отображён.

**Триггер:** Пользователь успешно авторизуется в приложении.

## Описание:

1. Пользователь успешно входит в приложение.
 
2. Система проверяет дату предыдущего входа.
 
3. Система обновляет счётчик серии в соответствии с датой предыдущего входа.
 
4. Пользователь видит анимацию огонька и текущее значение стрика.

## Расширения:

2.1. Система определяет, что предыдущий вход был вчера, и увеличивает счётчик на +1. Переход к шагу 4, анимация проигрывается.

2.2. Система определяет, что пользователь пропустил один или более дней, и сбрасывает счётчик до 1. Переход к шагу 4, анимация проигрывается.

2.3. Система определяет, что пользователь уже заходил сегодня. Значение счётчика не изменяется, анимация не проигрывается. Сценарий завершается.

# Use Case 4: Покупка предмета в магазине

**Вариант использования:** Покупка предмета

**Область действия:** Образовательное веб-приложение

**Уровень:** Цель пользователя

**Основное действующее лицо:** Ученик

**Участники:** Отсутствуют

**Предусловие:** Пользователь находится в разделе «Магазин» и выбрал предмет.

**Гарантии успеха:** Предмет добавлен в инвентарь, баланс монет уменьшен на стоимость предмета.

**Триггер:** Пользователь нажимает кнопку «Купить» под предметом.

## Описание:

1. Пользователь выбирает предмет и нажимает кнопку «Купить».
 
2. Система проверяет текущий баланс монет пользователя.
 
3. Система списывает монеты и добавляет предмет в инвентарь в рамках одной атомарной транзакции.
 
4. Пользователь видит обновлённый (уменьшенный) баланс и кнопку «Надеть»/«Использовать» вместо «Купить».

## Расширения:

2.1. Система определяет, что монет недостаточно.

2.2. Пользователь видит сообщение об ошибке «Недостаточно монет».

2.3. Сценарий завершается.

3.1. Добавление предмета в инвентарь завершается с ошибкой (технический сбой).

3.2. Транзакция откатывается, монеты не списываются.

3.3. Пользователь видит сообщение об ошибке и может повторить попытку.

# Use Case 5: Смена внешнего вида персонажа

**Вариант использования:** Экипировка предмета

**Область действия:** Образовательное веб-приложение

**Уровень:** Цель пользователя

**Основное действующее лицо:** Ученик

**Участники:** Отсутствуют

**Предусловие:** Пользователь находится в разделе «Инвентарь» и имеет минимум один купленный предмет.

**Гарантии успеха:** Внешний вид персонажа и/или связанных сцен обновлён на всех экранах приложения.

**Триггер:** Пользователь нажимает кнопку «Надеть»/«Использовать» на карточке купленного предмета.

## Описание:

1. Пользователь переходит в инвентарь и нажимает «Надеть»/«Использовать» на карточке предмета.
 
2. Система обновляет активный предмет в базе данных профиля.
 
3. Пользователь видит обновлённого персонажа (и/или связанные сцены — транспорт, локацию) с новым применённым предметом.

## Расширения:

1.1. Пользователь нажимает кнопку «Снять» на уже применённом предмете.

1.2. Система убирает предмет из активного слота.

1.3. Пользователь видит базовый вид без данного предмета. Сценарий завершается.

# Use Case 6: Стартовое тестирование (Определение уровня)

**Вариант использования:** Прохождение вводного теста

**Область действия:** Образовательное веб-приложение

**Уровень:** Цель пользователя

**Основное действующее лицо:** Ученик (новичок)

**Участники:** Отсутствуют

**Предусловие:** Пользователь открыл тест на уровень (регистрация не требуется).

**Гарантии успеха:** Пользователю назначен стартовый учебный модуль, соответствующий его знаниям; результат теста доступен для сохранения.

**Триггер:** Переход на экран стартового тестирования.

## Описание:

1. Пользователь видит на экране список из 6 заданий вводного теста.
 
2. Пользователь отвечает на задания в произвольном порядке (или нажимает «Не знаю») и нажимает «Завершить тест».
 
3. Система проверяет ответы и подсчитывает количество правильных.
 
4. Система назначает стартовый модуль в соответствии с результатом.
 
5. Пользователь видит разбор ответов, сообщение о назначенном модуле и кнопку «Сохранить результат и начать» (переход к регистрации).

## Расширения:

3.1. Система подсчитывает 0–2 правильных ответа. Система назначает модуль «Основы логики». Переход к шагу 5.

3.2. Система подсчитывает 3–4 правильных ответа. Система назначает модуль «Ветвления и циклы». Переход к шагу 5.

3.3. Система подсчитывает 5–6 правильных ответов. Система назначает модуль «Базовый синтаксис». Переход к шагу 5.

# Use Case 7: Получение медали (Достижения)

**Вариант использования:** Получение достижения (медали)

**Область действия:** Образовательное веб-приложение

**Уровень:** Системная реакция на цель пользователя

**Основное действующее лицо:** Ученик

**Участники:** Отсутствуют

**Предусловие:** Пользователь выполнил скрытое условие достижения (например, прошёл 10 уровней).

**Гарантии успеха:** Медаль привязана к профилю пользователя.

**Триггер:** Пользователь совершает действие, удовлетворяющее условиям достижения.

## Описание:

1. Пользователь совершает действие (например, завершает финальное задание теста).
 
2. Система в фоновом режиме проверяет условия для всех невыданных достижений.
   
3. Система подтверждает выполнение условия и привязывает новую медаль к профилю.
  
4. Пользователь видит всплывающее окно или push-уведомление «Получена новая медаль!».
   
5. Пользователь видит новую медаль в разделе своего профиля.

## Расширения:

2.1. Система проверяет условия и обнаруживает, что ни одно новое достижение не выполнено.

2.2. Сценарий завершается незаметно для пользователя.
